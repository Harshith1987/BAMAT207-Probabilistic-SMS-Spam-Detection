Abstract

Most of us get a few unwanted text messages every week: prize draws, "urgent" offers, links we would never click. Sorting them from genuine messages is a text-classification problem, and in this project I tackled it using nothing fancier than probability. The data comes from the UCI SMS Spam Collection (dataset ID: 228). The activity sheet lists 5,574 labelled messages. After I trimmed stray whitespace and dropped repeated texts, 5,160 unique messages were left for the main analysis: 4,518 ham (genuine) and 642 spam.

The statistics come first. I worked out the empirical prior probabilities from the class counts, then looked at how often the whole words "free", "prize", "win", "urgent" and "offer" show up, and computed P(Spam | Word) and P(Ham | Word) by counting messages. I checked Bayes' theorem against the real counts for "free". I also defined a binary random variable Y (1 for spam, 0 for ham) and derived its expectation and population variance.

For the classifier itself, messages were turned into word counts with CountVectorizer and fed to a Multinomial Naive Bayes model, using a stratified 80:20 split with random_state=42. The vectorizer was fitted on the training messages only, so nothing from the test set leaks in. In the recorded run the test accuracy was 98.26%, with spam precision of 95.08%, recall of 90.63% and an F1-score of 92.80%. The confusion matrix reads 898 true negatives, 6 false positives, 12 false negatives and 116 true positives. The sample message from the activity sheet, "Congratulations! You have won a free prize. Claim now.", was classified as spam with a model-generated P(Spam | Message) of about 0.999999802. These are real model outputs and not the illustrative 0.96 and 0.04 printed in the activity sheet.

Taken together, the project shows how empirical probability, conditional probability, Bayes' theorem, expectation, variance and a simple probabilistic classifier fit into one reproducible text-analysis workflow.

Keywords: SMS spam, prior probability, conditional probability, Bayes' theorem, Bernoulli random variable, expectation, variance, CountVectorizer, Multinomial Naive Bayes.

Chapter 1 – Introduction

1.1 Background

People use text messages for chatting, delivery updates, one-time passwords and, unfortunately, advertising and scams. Some of those messages promise prizes, push you to act quickly, or try to get personal details out of you. An SMS is short and has no real structure, so a filter has very little to go on besides the words themselves.

Probability is a natural tool for this. A prior probability tells us how common spam is before we read a message. A conditional probability tells us how often a word turns up inside a class, or how often a class turns up among messages that contain a given word. Bayes' theorem ties these together so that a prior belief can be updated once we see evidence. Naive Bayes then stretches the same idea from one word to a whole bag of words.

1.2 Problem Statement

The task is to build a Python system that takes an SMS and predicts one of two labels: Spam (unwanted or unsolicited) or Ham (genuine). Along the way it has to analyse the labelled data, calculate the probability quantities the activity asks for, test the classifier on messages it has not seen, and show class probabilities for a new message.

1.3 Aim and Objectives

  • Load the SMS Spam Collection from UCI using ucimlrepo, with a local ZIP fallback so the work can be reproduced offline.
  • Inspect the raw data, check for missing values, normalise labels and text, remove repeated messages, and encode Spam = 1 and Ham = 0.
  • Work out the count, percentage and prior probability of ham and spam, and plot the class distribution.
  • Calculate message-level conditional probabilities for free, prize, win, urgent and offer using case-insensitive whole-word matching.
  • Verify P(Spam | Free) with Bayes' theorem and compare it with the direct count.
  • Define a binary random variable for spam status and find its expectation and variance, both by formula and with NumPy.
  • Train and test a Multinomial Naive Bayes classifier on an 80:20 stratified split with a fixed random seed.
  • Evaluate it with accuracy, precision, recall, F1-score, a confusion matrix, a classification report and a look at the errors.
  • Test the example SMS from the activity sheet and provide a function for trying other messages.

1.4 Scope

The project covers binary classification of English SMS messages stored as text. It uses the supplied UCI dataset and one reproducible train-test split. In the word-level analysis a message counts if the whole word appears at least once; repeats inside the same message are not counted again. The machine-learning stage uses word-frequency features with Multinomial Naive Bayes.

1.5 Applications

  • Filtering unwanted SMS messages before the user reads them.
  • Flagging messages for manual review when the model gives a high spam probability.
  • Showing, in a practical way, how probability and Bayes' theorem sit inside an AI classification pipeline.
  • Serving as a baseline for later work on phishing detection, email filtering or notification screening.

Chapter 3 – Probability and Statistical Analysis

3.1 Notation and Counting Convention

Let N = 5,160 be the number of unique cleaned messages, N_S = 642 the number of spam messages and N_H = 4,518 the number of ham messages. For the word analysis, a message counts as containing a suspicious word if the entire word appears at least once, ignoring case.

3.2 Basic and Prior Probability

P(Spam) = N_S / N = 642 / 5,160 = 0.1244186
P(Ham) = N_H / N = 4,518 / 5,160 = 0.8755814

As percentages, 12.4419% of the cleaned messages are spam and 87.5581% are ham. The two add up to one (0.1244186 + 0.8755814 = 1.0000000). The dataset is clearly imbalanced.

3.4 Bayes' Theorem: Verification for "free"

P(Spam | Free) = [ P(Free | Spam) × P(Spam) ] / P(Free)
QuantityCount-based calculationValue
P(Free | Spam)144 spam messages containing free / 642 spam messages0.2242991
P(Spam)642 spam messages / 5,160 total messages0.1244186
P(Free)199 messages containing free / 5,160 total messages0.0385659
P(Free and Spam)144 spam messages containing free / 5,160 total messages0.0279070

Step 1 – the likelihood: P(Free | Spam) = 144 / 642 = 0.2242991.
Step 2 – multiply by the prior: 0.2242991 × 0.1244186 = 0.0279070.
Step 3 – divide by the marginal: P(Spam | Free) = 0.0279070 / 0.0385659 = 0.7236181.
The direct count gives 144 / 199 = 0.7236181, the exact same number.

3.5 Random Variable, Expectation, and Variance

Y = 1 if the message is Spam; Y = 0 if the message is Ham

Expectation:
E(Y) = 0 × P(Y = 0) + 1 × P(Y = 1) = 0 × 0.8755814 + 1 × 0.1244186 = 0.1244186

Variance:
Since 0² = 0 and 1² = 1, Y² = Y, which gives E(Y²) = E(Y) = p.
Var(Y) = E(Y²) − [E(Y)]² = p − p² = p(1 − p)
Var(Y) = 0.1244186 × (1 − 0.1244186) = 0.1089386
NumPy agrees: mean(Y) = 0.1244186 and var(Y, ddof=0) = 0.1089386.

Chapter 4 – Methodology, Architecture, and Algorithm

4.1 System Architecture

The implementation is a reproducible pipeline: Dataset Ingestion → Whitespace Normalization & Deduplication → Probability Analysis → Stratified Train/Test Split → CountVectorizer Feature Matrix → Multinomial Naive Bayes → Evaluation & Real-time Testing.

4.2 Data Split and Stratified Sampling

The cleaned data is divided with train_test_split(test_size=0.20, random_state=42, stratify=y). This gives 4,128 training messages (3,614 ham, 514 spam) and 1,032 test messages (904 ham, 128 spam).

4.3 Text Feature Extraction

CountVectorizer turns SMS text into a sparse count matrix. Lower-casing is active. The vectorizer is fitted on training text only (fit_transform) to prevent data leakage.

4.4 Multinomial Naive Bayes

P(c | x) ∝ P(c) × ∏ P(word_j | c)^(x_j)

Additive Laplace smoothing (α = 1) prevents zero-probability multiplication.
